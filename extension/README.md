# Amazon Scraper v4 采集助手（浏览器插件）

在亚马逊页面上一键把商品推给自建 Server 采集。自动识别当前是**商品列表页**、
**卖家店铺页**还是**商品详情页**，三种页面给三套不同的操作。

> 插件只负责**发现 ASIN**。完整详情（价格 / 库存 / 配送 / BuyBox / 卖家 /
> 变体 / 类目…）由 Server 派给 worker 采 —— 那一侧有 TLS 指纹模拟、代理轮换、
> 邮编切换、AIMD 自适应并发，浏览器里做不了也不该做。

## 安装

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选中本目录（`extension/`）
4. 点插件图标 → 右上角「选项」，填 Server 地址（例如 `http://192.168.1.10:8899`）
5. 点「**授权访问该地址**」，系统弹窗选「允许」
6. 点「测试连接」，看到版本号和在线 worker 数就算配好了

第 5 步不能跳过。浏览器要求扩展显式获得访问某个域名的许可；没有它，插件的
每一次请求都会失败，而错误信息看起来像「Server 地址不对」——实际地址完全正确。
换了 Server 地址要重新授权一次。

## 页内悬浮球与右侧面板

装好之后，任意亚马逊页面右侧会出现一个蓝色悬浮球 🔍，点它展开右侧面板 ——
不用每次去点浏览器工具栏的插件图标。面板会记住开合状态，翻页导航之后自己回来
（否则翻页采集途中每翻一页面板就消失一次）。

悬浮球上的绿色角标是**待采队列长度**，不展开面板也能看到攒了多少。

面板和工具栏弹窗装的是**同一份界面**（`src/popup.html`，用 iframe 复用）。
写两份的话以后每加一个按钮都要改两处，漏掉的那处不会报错、只会安静地少一个功能。

分工：

| 入口 | 何时用 |
|---|---|
| 页内悬浮球 → 右侧面板 | 干活。只在亚马逊页面上有 |
| 工具栏插件图标 → 弹窗 | 配置、看队列。任何页面都能开 |

### 页面是实时识别的

面板不需要手动刷新：content script 用 `MutationObserver`（DOM 变化）+
history 补丁（`pushState` 导航）持续重新识别，页面类型或商品数一变就更新面板。

这两条都是实测踩出来的：

- Amazon 详情页的骨架**异步渲染**，打开页面立刻点插件时 `#productTitle` 还不存在。
  旧版判成"未识别到页面"，要关掉重开才好 —— 现在 URL 路径里的 `/dp/ASIN`
  一命中就认，标题和卖家等渲染好了自动补上，中间显示"页面加载中…"。
- Amazon 的翻页/筛选很多走 `pushState`，**不重新加载文档**。没有 URL 监听的话，
  面板会一直显示上一页的信息，而用户完全看不出它已经过期。

万一还是遇到没跟上的情况，面板右上角有「刷新」可以手动重算。

## 三种页面

### 商品列表页

搜索结果、类目页、榜单页、品牌旗舰店…… 只要页面上有商品网格就算。

- **采集本页并推送** —— 读当前页所有 ASIN，推给 Server 建一个批次
- **翻页采集**（开关）—— 自动一页页翻下去，每页读完立刻推送

翻页是**一页一推**的，全部落进同一个批次。中途关掉标签页只会丢掉还没翻到的
那些页，已推送的不受影响。翻页期间插件图标上的数字是已完成页数。

翻页间隔默认 2.5 秒，可在选项页调。别调太小 —— 连着打 Amazon 很快会吃到
验证码，那时整个任务会从「慢一点」变成「后面几页全是空的」。

### 卖家店铺页

`/s?me=A2L77EE7U53NWQ` 这类页面。它的 DOM 和搜索结果页一模一样，所以上面
那两个按钮照样能用，**另外**多一个：

- **采集该卖家全部商品** —— 把卖家 ID 交给 Server，由服务端翻遍整个店铺

服务端翻页比在浏览器里翻快得多也全得多（多 worker 并发 + 代理轮换 + 最多 75 页），
而且不占用你的浏览器。想要整店数据就用这个，别用翻页采集。

Amazon 自营店（`ATVPDKIKX0DER`）会给出警告并不建议整店采集 —— 那是数百万商品。

### 商品详情页

- **加入待采队列** —— 攒着，逛完一批一次性提交
- **同时采集该卖家的全部商品**（勾选）—— 连这个商品的卖家整店一起采

队列存在浏览器本地，关掉浏览器也在。提交时会创建**两个**批次：

| 批次 | 内容 |
|---|---|
| `ext_queue_<时间戳>` | 你勾的那些商品 |
| `ext_queue_<时间戳>_sellers` | 勾了"整店"的那些卖家 |

拆成两个是因为规模差得太远：你勾了 5 个商品，而 5 家店可能有几万个商品。
混在一个批次里，进度条会永远卡在 1%，你根本看不出自己勾的那 5 个采完没有。

**卖家读不出来时**：部分详情页（自营商品、Amazon 改版、异步渲染没跑完）
拿不到三方卖家，那个勾选会灰掉。这时可以先加入队列，提交前让插件问一次
服务端 —— 如果这个 ASIN 以前采过，库里就有卖家信息。**只会回库里真有的**，
查不到就还是查不到：给一个猜的卖家会让你采回一整店无关商品，且完全看不出是错的。

## 选项

| 项 | 说明 |
|---|---|
| Server 地址 | 自建控制台地址，不带路径 |
| 管理令牌 | 服务端配了 `ADMIN_TOKEN` 才需要 |
| 配送邮编 | 留空则用服务端默认 |
| 卖家整店采集深度 | `发现 + 抓详情` / `仅发现 ASIN` |
| 翻页上限 | 弹窗里的默认值 |
| 翻页间隔 | 见上面的说明 |
| 详情采集开启截图 | 对应 Server 的批次级截图开关 |
| 保留广告位商品 | 默认丢弃 —— 广告位每次请求都不同，且会挤掉自然位的采集配额 |

## 它是怎么工作的

```
content script          service worker              Server
（跑在亚马逊页面上）      （跑在扩展自己的源上）
     │                        │                        │
     │ 读 DOM / 翻页           │ 存状态 / 发请求          │
     ├── 页面类型 ──────────► │                        │
     ├── 本页 ASIN ─────────► ├── POST collect ──────► │ 建批次 + 建任务
     │ ◄── 继续 / 停止 ────── │                        │
     │ (location = 下一页)    │                        │
```

两侧分工是被浏览器的规则逼出来的，不是风格选择：

- **只有 content script 能碰页面**，但它跑在 `amazon.com` 这个源上，
  直接请求自建 Server 属于跨源，会被 CORS 拦掉；
- **只有 service worker 能跨源**（凭 `host_permissions`），但它碰不到页面 DOM。

翻页状态存在 `chrome.storage.local` 而不是内存里，也是同理：翻页 = 页面导航，
导航会销毁 content script 的整个执行环境，一个跨页的循环根本活不到第二页。
MV3 的 service worker 自己也随时会被回收，所以状态每次现读现写。

## 文件

```
extension/
  manifest.json      MV3 清单
  src/
    page.js          页面识别 + ASIN/卖家抽取（纯函数，可单测）
    content.js       跑在亚马逊页面上：读 DOM、翻页、实时检测、悬浮球 + 面板
    background.js    service worker：设置、队列、翻页状态机、所有 Server 请求
    popup.html/js/css   操作界面。**弹窗与面板共用这一份**
    options.html/js     选项页
  icons/             图标
```

页内 UI 挂在 **Shadow DOM** 里。不这么做的话两边互相污染：Amazon 有
`button { ... }` 这类裸标签规则会把按钮样式冲掉，而我们的样式也会漏进页面。

`page.js` 是唯一依赖 Amazon 前端实现细节的地方（`s-result-item`、
`s-pagination-next`、`#sellerProfileTriggerId` 这些类名会随 Amazon 改版而变），
所以它有一份规格用例钉着：

```bash
npm install jsdom          # 仓库根目录，一次即可
node tests/extension_page_spec.js
```

跑 `pytest tests/` 时它也会跟着跑（`tests/test_extension_page_js.py`）；
没装 Node 或 jsdom 就 skip，不会变红。

## 服务端对接的三个端点

| 端点 | 用途 |
|---|---|
| `GET /api/extension/ping` | 测试连接，回版本 / 默认邮编 / 在线 worker 数 |
| `POST /api/extension/collect` | 推 ASIN 与卖家 ID |
| `POST /api/extension/resolve-sellers` | 按 ASIN 反查已采到的卖家 |

`collect` 的**同名批次是追加**（不是 `409`），那是翻页采集一页一推的前提。
注意这与 `/api/upload` / `/api/batches` 的撞名语义**相反**，两者都是有意的，
细节见 `server/api/extension.py` 的模块文档。
